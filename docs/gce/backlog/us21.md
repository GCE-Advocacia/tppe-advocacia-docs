## História de Usuário

Como equipe de desenvolvimento, quero hospedar o sistema (frontend, API, banco de
dados e arquivos) em serviços de nuvem gratuitos para que ele fique disponível
online sem depender da máquina de um membro do grupo.

## Critérios de Aceitação

- O frontend deve estar acessível publicamente por HTTPS no Netlify;
- A API deve estar acessível por HTTPS no Render e responder em `/api/v1/health`;
- O banco de dados no Neon deve aceitar apenas conexões autenticadas e com SSL;
- As notificações de vencimento devem continuar sendo enviadas nos horários previstos;
- Os documentos anexados, as imagens da Landing Page e as logos não devem ser perdidos após reinício ou novo deploy da API;
- Nenhum dos serviços utilizados deve gerar custo;
- O sistema não deve depender da máquina de nenhum membro do grupo;
- As credenciais de administrador devem permitir o acesso ao painel.

## Observações

- A [US20](./us20.md) fez o deploy em uma máquina de um membro do grupo. Esta história
  move o sistema para serviços de nuvem gratuitos, por pedido do professor.
- No plano gratuito do Render, a API hiberna após cerca de 15 minutos sem acesso, e a
  primeira requisição seguinte pode levar até 1 minuto.
- O agendador (alertas de vencimento, lembretes de pagamento e sincronizações) roda dentro
  da API e só executa enquanto ela está ativa. Por isso um workflow do GitHub Actions
  acessa `/api/v1/health` a cada 10 minutos. A equipe avaliou disparar as notificações por
  um endpoint protegido chamado pelo GitHub Actions e optou pelo keep alive, mais simples.
- Os agendamentos do GitHub Actions podem atrasar em horários de pico, então a API ainda
  pode hibernar de vez em quando. Uma tarefa diária que coincidir com esse intervalo não é
  executada naquele dia.
- O GitHub desativa workflows agendados após 60 dias sem atividade no repositório. Se isso
  acontecer, o workflow deve ser reativado na aba Actions.
- O plano gratuito do Render tem 512 MB de RAM, não oferece workers em segundo plano e
  inclui 750 horas por mês. Por isso a API roda com 1 worker, o agendador roda dentro dela
  (sem envio duplicado) e o serviço `scheduler` separado deixa de ser usado. Ela deve ser
  o único serviço gratuito na conta do Render.
- O servidor do Render usa UTC. Como o Brasil não tem horário de verão, 09:00 UTC
  corresponde a 06:00 em `America/Sao_Paulo`.
- O disco do Render é apagado a cada deploy ou reinício, por isso as imagens vão para o
  Object Storage do Neon e os documentos para o Google Drive. O navegador lê as imagens
  direto do bucket, sem passar pela API.
- O plano gratuito do Neon oferece 1 GB de banco, 5 GB de Object Storage e 5 GB de
  transferência de saída por mês por projeto. As imagens comprimidas ocupam poucos MB, e o
  cabeçalho de cache evita que sejam baixadas de novo a cada visita.
- O Object Storage do Neon estava em beta quando esta história foi implementada.
- Contas de serviço do Google não têm cota de armazenamento no Drive, por isso os
  documentos são enviados com OAuth da conta do escritório.
- Sem domínio verificado, o Resend só envia e-mails para o dono da conta.
- Os limites dos planos gratuitos devem ser conferidos na hora da configuração.

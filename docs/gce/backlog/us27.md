## História de Usuário

Como escritório de advocacia, quero que a hospedagem do sistema e as integrações com o
Google fiquem em contas do próprio escritório para que o sistema não dependa de contas
pessoais dos membros do grupo e continue funcionando depois do fim da disciplina.

## Tarefas

| Tarefa | Situação |
| --- | --- |
| Criar o projeto no Google Cloud na conta do cliente, com as APIs do Google usadas pelo sistema e a credencial OAuth | Concluída |
| Cadastrar na credencial OAuth as URLs de callback da API em produção | Concluída |
| Criar o banco PostgreSQL e o Object Storage no Neon na conta do cliente | Concluída |
| Publicar a API no Render na conta do cliente | Concluída |
| Publicar o frontend no Netlify na conta do cliente, apontando para a nova URL da API | Concluída |
| Atualizar as variáveis de ambiente no Render e no Netlify com as novas credenciais | Concluída |

## Critérios de Aceitação

- O frontend, a API, o banco de dados e as imagens devem estar hospedados em contas do cliente;
- As integrações com o Google devem usar a credencial OAuth do projeto do cliente;
- O sistema deve continuar acessível por HTTPS e responder em `/api/v1/health`;
- Nenhum serviço do sistema deve depender de conta pessoal de membro do grupo;
- Os serviços devem continuar nos planos gratuitos.

## Observações

- Esta história dá continuidade à [US21](./us21.md), que publicou o sistema no Netlify,
  no Render e no Neon usando contas do grupo.
- Ao trocar a credencial OAuth, as conexões feitas com a credencial antiga deixam de valer.
  Por isso o Google Drive precisa ser conectado de novo pelo administrador.
- As URLs de callback cadastradas no Google Cloud precisam ser idênticas às variáveis
  `GOOGLE_*_REDIRECT_URI` da API. Se não forem, o Google mostra `redirect_uri_mismatch`.
- A variável `VITE_API_URL` do Netlify é lida no build. Depois de mudar a URL da API, é
  preciso fazer um novo deploy do frontend.
- O passo a passo de cada serviço continua no `DEPLOY.md` do repositório do backend.

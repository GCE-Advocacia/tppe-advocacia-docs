## História de Usuário

Como administrador, quero escolher, para cada funcionário, quais áreas do sistema ele pode
acessar, para controlar quem vê e altera as informações do escritório.

## Tarefas

- Criar a tabela de permissões com todas as abas da área do sistema;
- Criar a tabela que liga cada usuário às abas permitidas;
- Migrar os acessos atuais dos funcionários para as novas permissões;
- Exigir a permissão da aba em todas as rotas do sistema;
- Liberar para cada aba os dados que a sua tela usa de outras abas;
- Exibir uma checkbox para cada aba na tela de usuários;
- Mostrar no menu apenas as abas permitidas ao funcionário;
- Bloquear o acesso direto pela URL às abas não permitidas;
- Exibir uma página de aviso para o funcionário sem nenhuma aba.

## Critérios de Aceitação

- Deve existir uma permissão para cada aba da área do sistema;
- Apenas o administrador deve poder marcar e desmarcar as permissões;
- O funcionário deve acessar apenas as abas permitidas;
- A permissão de uma aba deve liberar a tela inteira, sem liberar outras abas;
- A revogação da permissão deve valer imediatamente;
- Nenhum funcionário existente deve perder acesso na atualização do sistema;
- O sistema deve respeitar as permissões do usuário.

## Observações

- Esta história substitui a permissão única de vencimentos da [US11](./us11.md): a permissão
  `can_view_payments` passou a ser a permissão da aba Pagamentos.
- São 12 abas com permissão: Landing Page, Artigos, Leads, Clientes, Agenda, Pagamentos,
  Processos, Tarefas, Notificações, Logs DataJud, Feriados e Financeiro. A aba Usuários é
  sempre exclusiva do administrador.
- Administradores sempre acessam todas as abas. Anonimizar clientes e alterar papéis e
  permissões continuam exclusivos do administrador.
- Uma permissão concedida aparece no menu a partir do próximo login do funcionário. A
  revogação bloqueia o acesso imediatamente.
